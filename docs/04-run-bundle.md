# The run bundle

The one artefact that crosses every boundary: produced by the run flow, read by the analyzers,
generated by the fault suite, read by any diagnostic method, submitted by third parties. This
document is its contract. Milestone 0 implements it on synthetic bundles; milestone 1 records
real ones and this document is corrected against them, the way demosift's format document was
corrected against real datasets.

## 1. Layout

```
<bundle>/
├── manifest.json        identity, versions, dataset, inspection, config hash, seed, hardware, overrides
├── config.yaml          the resolved configuration, exactly as the framework received it
├── metrics.parquet      step, split, name, value, wall_time
├── events.jsonl         dated events: start, checkpoint, lr change, resume, eval, fault hooks' silence
├── eval/
│   └── <checkpoint>/    results.json (episodes, seeds, successes, rate, interval), videos/ (a sample)
├── checkpoints/         references (path or Hub id, sha256, step); weights are not in the bundle by default
├── export/              onnx model reference, parity.json, latency.json
├── env/                 frozen dependencies, framework version, CUDA and driver versions, git SHA of the run's code
└── logs/                redacted stdout and stderr, bounded
```

A bundle is a directory or a zip of one. Its **identity** is the sha256 of `manifest.json`;
two bundles with the same manifest are the same run.

## 2. The manifest

| Field | Holds | Why |
|---|---|---|
| `trainsift_version`, `framework`, `framework_version` | What produced the bundle | Analyzers and retrieval are version-aware |
| `dataset.id`, `dataset.revision` | The Hub id and the commit sha | The revision is the dataset's version; no other versioning of source data |
| `dataset.inspection` | demosift's `Inspection`, `model_dump(mode="json")` | The data facts, computed elsewhere (D7) |
| `dataset.audit_override` | `null` or `{reason, who, when}` | A run on failed data says so |
| `config_hash` | sha256 of `config.yaml` | Reproducibility and deduplication |
| `seed` | The seed propagated to every source of randomness the adapter controls | Rule 7 |
| `hardware` | Accelerator model and count, RAM, the machine's class | Throughput numbers need it |
| `created_at`, `finished_at`, `status` | Timing and outcome (`completed`, `stopped`, `crashed`) | A crashed run is a bundle too |
| `redaction` | Version of the redaction pass and the count of replacements | Proof it ran |

The manifest never holds a fault id, a scenario name or a gold label (rule 5). A campaign's
answers live in the campaign, sealed.

## 3. Metrics and events

`metrics.parquet` is long-form: one row per `(step, split, name)`. Names are the framework's,
mapped to a small canonical set the analyzers know (`loss`, `loss/<component>`, `lr`,
`grad_norm`, `eval/success_rate`, `throughput/samples_per_s`), with the raw name kept in a
column. `events.jsonl` is append-only; each line has `time`, `step`, `kind`, `data`. The fault
hooks write nothing to either: their silence is the point.

## 4. Bounds and redaction

Every file has a size bound and the bundle has a total bound; both are configuration values,
set at milestone 0 and journaled. A bundle over the bound is refused with
`BundleTooLargeError`, never truncated silently. Readers parse with explicit schemas: an
unknown manifest version, a metrics table with the wrong columns or a malformed event line are
named errors (`UnsupportedBundleError`), never a crash and never a guess.

The redaction pass runs before a bundle leaves the machine, and again at intake by anything
that accepts a bundle from another machine: absolute paths replaced by the bundle-relative form, user names and host names replaced,
anything that matches a token or key pattern replaced with a marker and counted. The count is
in the manifest so that a bundle with zero replacements can be told from one that was never
redacted.

## 5. What is deliberately not in the bundle

Weights, by default: a checkpoint is referenced by path or Hub id and sha256, so that a
bundle stays small enough to upload and to publish by the hundred. Datasets, ever: the
revision is the reference. Anything the analyzers do not read: a bundle is not an archive of
a run, it is the record a diagnosis needs.

## 6. Renderings

`to_json(bundle)` is the storable form and what a tool receives. `to_markdown(bundle)` is a
report: identity, dataset and inspection verdict, the config's salient fields, the curves as
numbers at fixed fractions of training, the evaluation table, the export results. The
renderings are deterministic and pinned by fixture tests, as demosift's are.

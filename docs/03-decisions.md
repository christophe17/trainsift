# Decisions

Short records, newest last. A decision is changed by a new entry, not by editing an old one.

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-09-29 | Name the project **trainsift** | The pair with demosift reads in one second: demosift sifts the demonstrations before training, trainsift sifts the training after. Same form, two morphemes, a verb, lowercase. `trainsift.io` and `.com` free, PyPI free, no GitHub repository of that name, no homonymous product; `runsift`, the first choice, is a Y Combinator company. `faultsift` and `policysift` were free too and are kept as fallbacks |
| D2 | 2026-09-29 | **This repository is the deterministic platform and the benchmark, and nothing else.** Any method that reasons over bundles with a model — an agent, a single model call — lives outside it, as does anything that exists because people use a service (sign-in, quota, infrastructure) | demosift's D12 reasons apply unchanged, and a fifth is specific to a benchmark: the method being scored must not live with the scorer. What is true of a run is computed here and released by tag |
| D3 | 2026-09-29 | **This repository is the roadmap's phase 4 deliverable**, not a project next to it | The roadmap asks for a robot-learning training platform in a standalone repository: ingestion and versioning, reproducible distributed training, an evaluation harness, a deployment path. That is this package's run flow. The diagnosis flow and the fault suite are what make the platform measured rather than merely built, and they are what any diagnostic method is measured against. One artefact, two goals; no diversion |
| D4 | 2026-09-29 | Python 3.12, `uv`, a single `src/` package, core plus extras; Apache-2.0 | The shape of demosift, known and green. The core (bundle, analyzers, faults, scoring) installs without torch, so the scorer runs anywhere, on a laptop, in a Lambda, in a third party's CI. Apache-2.0 is the ecosystem's licence and demosift's |
| D5 | 2026-09-29 | **LeRobot is the first framework; the bundle is framework-agnostic.** A second adapter, PPO locomotion in Isaac Lab with `rsl_rl`, comes at milestone 4 | LeRobot is where the author's data tool lives, where the users are, and where small policies train cheaply on public datasets. The bundle records a metrics table, a config, a dataset reference, evaluation results and an environment, which no framework owns, so the second adapter changes nothing in the diagnosis flow. Isaac Lab waits for the phase 2 policy to exist and for a GPU budget |
| D6 | 2026-09-29 | **The run bundle is the contract**: local, self-contained, bounded, redacted; an experiment tracker is an exporter, never the source of truth | Anything downstream, analyzers, scorer, the lab notebook, a third party, must work from a directory alone, offline, without an account anywhere. A tracker's API is a dependency on a vendor, a network and a token for the thing the benchmark rests on. Exporting to W&B or TensorBoard stays possible, and is one-way |
| D7 | 2026-09-29 | **demosift is a dependency and a gate.** A run inspects its dataset with the pinned release before training; the inspection is stored in the bundle; a failing check blocks unless `--allow-failed-audit`, which is recorded | The platform that claims to know why runs fail cannot train on data it did not look at. Storing the inspection makes the data facts of a bundle demosift's facts, which are tested and released elsewhere, and gives the `data` analyzers their ground. The override exists because a research run on knowingly broken data is legitimate, as long as the bundle says so |
| D8 | 2026-09-29 | **Analyzers report facts, never causes.** The only cause-naming code here is the `rules` baseline, kept in `score` and treated as one method among others | A finding is a checked fact with evidence, testable to the digit. A cause is an inference, which is what methods are scored on. Mixing the two would let the platform grade itself. The `rules` baseline lives here so that the benchmark ships with its own first line, and it is scored like anyone else |
| D9 | 2026-09-29 | **The fault suite lives here, with sealed answers and a frozen protocol.** Ids `TRAINSIFT-<CAT>-NN`; the method is tinct's Culprit; no component name for the suite for now | A benchmark's answers must be produced by code the scored methods cannot influence, which is this repository's whole reason to be separate. Culprit's four rules (versioned scenario, explicit parameters, applied without the pipeline knowing, verified as applied) carry over unchanged. A name for the suite was considered and deferred: Culprit is tinct's, and a second named component needs a reason it does not have yet |
| D10 | 2026-09-29 | **The gold set is published on the Hub** as a dataset of bundles, with the sealed answers in a separate, later-released file; the organization is undecided | A benchmark nobody can download is a claim. Publishing the bundles lets anyone score their method; releasing the answers after a first scoring window is the usual protection against fitting to them. The Hub is where the users already are. The organization question is demosift's D9 again and is answered once, for both |
| D11 | 2026-09-29 | **No model, no agent, no cloud, no deployment here** | demosift's D18 and D15, learned once and not relearned: a tool repository has no business calling a model or deploying itself. A diagnostician lives outside, in the program's private lab or in a third party's hands; the platform is what it is measured against |
| D12 | 2026-09-29 | **Evaluation runs in `gym-pusht` and `gym-aloha` on CPU** for the first pass; LIBERO or another suite only when a policy exists that needs it. Success rate with a Wilson interval; N and S set at milestone 1 from the measured interval width, then fixed by the protocol | Both simulators run under MuJoCo without a GPU, which keeps the harness testable in CI and the campaign affordable. The number of episodes is not chosen by habit but from the interval width the protocol wants, which is a measurement of milestone 1 |
| D13 | 2026-09-29 | **GPUs are rented on demand and every hour is journaled with its cost.** The campaign's GPU budget is a bound set at milestone 2 and published | The scale caveat of the author's profile is answered by measured runs, not by owning hardware. A benchmark whose cost of production is a number is reproducible; one whose cost is a vibe is not |
| D14 | 2026-09-29 | **Milestone 0 needs no GPU and no framework.** Synthetic bundles first, replaced by recorded ones at milestone 1 | The contract, the analyzers and the scorer are the part everyone downstream depends on, including any diagnostic method, which can start on them the day they exist. Waiting for a trained policy to define a bundle would put the framework in charge of the contract |
| D15 | 2026-09-29 | GitHub organization **undecided**; the repository starts under the author's personal account | demosift's D9; a repository moves later without losing history or links |
| D16 | 2026-10-08 | **World models enter in two roles only, both outside the library's code: a caller-supplied evaluator behind the harness interface, and a framework under test behind an adapter.** The harness's evaluator is an interface; the simulator implementation (D12) is its first. A world-model evaluator, supplied by the caller for real-robot datasets that have no simulator (milestone 3: OXE, DROID), is a candidate for milestone 3, published only with its reliability measured against real rollouts, which in this program means tinct's. A model-based RL adapter (TD-MPC2 or DreamerV3) with its own fault family is a candidate second framework for milestone 4; it waits for no phase 2 policy, so it may come before Isaac Lab (D5's order, not its substance). An `EVAL` scenario "the evaluator lies" (a world model that turns a failure into a success) is reserved for a `v2.0` protocol | Rule 1 stands: no model here, as with demosift's `VisionJudge` and tinct's D12 (world models around the bench, never inside). The harness as specified has nothing to say about a policy trained on a real-robot dataset, which is what milestone 3 ingests; evaluating policies inside a world model is the 2026 answer (WorldEval, Ctrl-World, the discrete-diffusion evaluator at ICML 2026), and its known weak point is reliability, which only real rollouts can measure. The model-based adapter is the kind of extension the framework-agnostic bundle exists for, and it is where the author's study of world models produces a deliverable rather than a diversion. Nothing opens now: the program board's open block is demosift's first pass |
| D17 | 2026-10-15 | **The agent comparison lives in the program's private lab.** "Do agents diagnose a run better than a rule set and than a model alone" is a question of the program's supervision thesis, and it is answered in the program's private lab (`~/Roadmaps/program/docs/03` §5): one notebook, outside this repository, run at milestone 2 on the frozen campaign, N runs with bootstrap intervals, its diagnoses scored with `score_diagnoses` exactly as a third party's submission. `model-alone` and a graph of agents are the second and third lines of the table (`docs/06` §4), produced by that notebook. Milestone 2 waits for none of it | The comparison needs a fixed task and a reference, both of which milestone 2 provides, so it is a notebook, not a product. What only a product would need — the quality of an explanation, its faithfulness, the usefulness of a fix — has no instrument in the program, and `docs/06` §6 says so. D2's boundary stands: the method being scored does not live with the scorer; it lives in the notebook |
| D18 | 2026-10-16 | **Two papers are milestone deliverables, under the same honesty rules as the code.** Milestone 1 keeps a discrepancy log during the reproduction of ACT and Diffusion Policy and delivers a reproducibility-paper draft in TMLR format; milestone 2 delivers an evaluation-benchmark-paper draft whose ablation section is the D17 comparison. Every number in a paper cites the `JOURNAL.md` entry or the bundle that produced it; a failure to reproduce is a result; drafts are written outside the public repository until submission; **submission, upload or posting is the author's act, never a session's** | The author's Research Engineer roadmap (`~/Roadmaps/roadmap-research-engineer`, its `docs/03`) makes this repository its research vehicle: milestone 1 is a reproduction by construction and milestone 2 a benchmark by construction, and what they lacked to count as research was the written report. A discrepancy log is kept during the work because it reconstructs badly afterwards; the papers are drafts because publishing is a decision the author takes with venue and date in hand (the ML Reproducibility Challenge is a NeurIPS track through TMLR since 2026; the Datasets & Benchmarks track became Evaluations & Datasets in 2026). Recorded from a session in that repository at the author's request, as this entry says |
| D19 | 2026-10-16 | **An LLM post-training adapter with its own fault family is milestone 2B**, between the fault suite and scale, as a skeleton to be detailed when it opens; it amends D5's order (a second framework before Isaac Lab, as D16 already allowed), not D5's substance (the bundle stays framework-agnostic). Rule 1 is untouched: the adapter *trains* a model as the LeRobot adapter does; nothing here *reasons* with one | The author's target became a generalist Research Engineer role on 2026-10-15, robotics remaining the domain where depth is proven and the infra side a pillar; the benchmark is generalist the day it scores methods on post-training runs as well as on policy runs, and the same bundle, analyzers and scorer serve both. The fault family is where post-training actually breaks (reward hacking, KL, templates, contamination), which the LeRobot family does not cover. It is a skeleton because trainsift is not open and milestone 0 has not started; the detailed specification is module R1.4 of the Research Engineer roadmap |

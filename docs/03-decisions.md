# Decisions

Short records, newest last. A decision is changed by a new entry, not by editing an old one.

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-09-29 | Name the project **trainsift** | The pair with demosift reads in one second: demosift sifts the demonstrations before training, trainsift sifts the training after. Same form, two morphemes, a verb, lowercase. `trainsift.io` and `.com` free, PyPI free, no GitHub repository of that name, no homonymous product; `runsift`, the first choice, is a Y Combinator company. `faultsift` and `policysift` were free too and are kept as fallbacks |
| D2 | 2026-09-29 | **Two repositories, the same boundary as demosift and demosift-web.** This one is the deterministic platform and the benchmark; `trainsift-web` is the hosted diagnostician with its agents, corpus, sign-in, quota and infrastructure | The four reasons of demosift's D12 apply unchanged, and a fifth is specific to a benchmark: the method being scored must not live with the scorer. What is true of a run is computed here and released by tag; what exists because people use the service is built there |
| D3 | 2026-09-29 | **This repository is the roadmap's phase 4 deliverable**, not a project next to it | The roadmap asks for a robot-learning training platform in a standalone repository: ingestion and versioning, reproducible distributed training, an evaluation harness, a deployment path. That is this package's run flow. The diagnosis flow and the fault suite are what make the platform measured rather than merely built, and they are what the hosted instance needs. One artefact, two goals; no diversion |
| D4 | 2026-09-29 | Python 3.12, `uv`, a single `src/` package, core plus extras; Apache-2.0 | The shape of demosift, known and green. The core (bundle, analyzers, faults, scoring) installs without torch, so the scorer runs anywhere, on a laptop, in a Lambda, in a third party's CI. Apache-2.0 is the ecosystem's licence and demosift's |
| D5 | 2026-09-29 | **LeRobot is the first framework; the bundle is framework-agnostic.** A second adapter, PPO locomotion in Isaac Lab with `rsl_rl`, comes at milestone 4 | LeRobot is where the author's data tool lives, where the users are, and where small policies train cheaply on public datasets. The bundle records a metrics table, a config, a dataset reference, evaluation results and an environment, which no framework owns, so the second adapter changes nothing in the diagnosis flow. Isaac Lab waits for the phase 2 policy to exist and for a GPU budget |
| D6 | 2026-09-29 | **The run bundle is the contract**: local, self-contained, bounded, redacted; an experiment tracker is an exporter, never the source of truth | Anything downstream, analyzers, scorer, the hosted instance, a third party, must work from a directory alone, offline, without an account anywhere. A tracker's API is a dependency on a vendor, a network and a token for the thing the benchmark rests on. Exporting to W&B or TensorBoard stays possible, and is one-way |
| D7 | 2026-09-29 | **demosift is a dependency and a gate.** A run inspects its dataset with the pinned release before training; the inspection is stored in the bundle; a failing check blocks unless `--allow-failed-audit`, which is recorded | The platform that claims to know why runs fail cannot train on data it did not look at. Storing the inspection makes the data facts of a bundle demosift's facts, which are tested and released elsewhere, and gives the `data` analyzers their ground. The override exists because a research run on knowingly broken data is legitimate, as long as the bundle says so |
| D8 | 2026-09-29 | **Analyzers report facts, never causes.** The only cause-naming code here is the `rules` baseline, kept in `score` and treated as one method among others | A finding is a checked fact with evidence, testable to the digit. A cause is an inference, which is what methods are scored on. Mixing the two would let the platform grade itself. The `rules` baseline lives here so that the benchmark ships with its own first line, and it is scored like anyone else |
| D9 | 2026-09-29 | **The fault suite lives here, with sealed answers and a frozen protocol.** Ids `TRAINSIFT-<CAT>-NN`; the method is tinct's Culprit; no component name for the suite for now | A benchmark's answers must be produced by code the scored methods cannot influence, which is this repository's whole reason to be separate. Culprit's four rules (versioned scenario, explicit parameters, applied without the pipeline knowing, verified as applied) carry over unchanged. A name for the suite was considered and deferred: Culprit is tinct's, and a second named component needs a reason it does not have yet |
| D10 | 2026-09-29 | **The gold set is published on the Hub** as a dataset of bundles, with the sealed answers in a separate, later-released file; the organization is undecided | A benchmark nobody can download is a claim. Publishing the bundles lets anyone score their method; releasing the answers after a first scoring window is the usual protection against fitting to them. The Hub is where the users already are. The organization question is demosift's D9 again and is answered once, for both |
| D11 | 2026-09-29 | **No model, no agent, no cloud, no deployment here** | demosift's D18 and D15, learned once and not relearned: a tool repository has no business calling a model or deploying itself. The diagnostician is the hosted instance's; the platform is what it is measured against |
| D12 | 2026-09-29 | **Evaluation runs in `gym-pusht` and `gym-aloha` on CPU** for the first pass; LIBERO or another suite only when a policy exists that needs it. Success rate with a Wilson interval; N and S set at milestone 1 from the measured interval width, then fixed by the protocol | Both simulators run under MuJoCo without a GPU, which keeps the harness testable in CI and the campaign affordable. The number of episodes is not chosen by habit but from the interval width the protocol wants, which is a measurement of milestone 1 |
| D13 | 2026-09-29 | **GPUs are rented on demand and every hour is journaled with its cost.** The campaign's GPU budget is a bound set at milestone 2 and published | The scale caveat of the author's profile is answered by measured runs, not by owning hardware. A benchmark whose cost of production is a number is reproducible; one whose cost is a vibe is not |
| D14 | 2026-09-29 | **Milestone 0 needs no GPU and no framework.** Synthetic bundles first, replaced by recorded ones at milestone 1 | The contract, the analyzers and the scorer are the part everyone downstream depends on, including the hosted instance, which can start on them the day they exist. Waiting for a trained policy to define a bundle would put the framework in charge of the contract |
| D15 | 2026-09-29 | GitHub organization **undecided**; the repository starts under the author's personal account | demosift's D9; a repository moves later without losing history or links |
